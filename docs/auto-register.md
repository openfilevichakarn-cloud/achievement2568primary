# ติดตั้งระบบสมัครใช้งานอัตโนมัติ (ตรวจสลิป + ออกรหัสสิทธิ์)

ลูกค้าเลือกชั้น → โอนเงินเข้าบัญชีร้าน → กรอกข้อมูลโรงเรียน เวลาโอน และแนบสลิปในหน้า `register.html`
→ Edge Function `auto-register` ส่งสลิปไปตรวจกับ **EasySlip** (อ่าน QR บนสลิปแล้วดึงข้อมูลจริงจากธนาคาร)
→ ถ้า **ยอดเงิน = ราคา**, **บัญชีผู้รับ = บัญชีร้าน**, **เวลาโอนตรงกับที่ลูกค้ากรอก (± 15 นาที)**, **สลิปไม่เก่าเกิน 3 วัน** และ **ไม่เคยใช้มาก่อน**
→ ออกรหัสสิทธิ์และแสดงให้ลูกค้าทันที / ไม่ผ่าน → คำสั่งซื้อไปรอใน `admin.html` ให้ผู้ดูแลดูสลิปแล้วกดอนุมัติเอง

> ทำไมไม่อ่านตัวเลขจากรูปสลิปเอง: สลิปปลอม (แต่งรูป) ทำได้ง่ายและใช้สลิปจริงใบเดิมซ้ำได้ — บริการตรวจสลิปยืนยันกับข้อมูลธนาคารจริงผ่าน QR และเราเก็บเลขอ้างอิงธุรกรรมไว้กันสลิปซ้ำ

## ขั้นตอนติดตั้ง (ครั้งเดียว)

1. **ฐานข้อมูล** — Supabase → SQL Editor → วางไฟล์ `sql/orders.sql` → Run
2. **บริการตรวจสลิป** — สมัครที่ https://easyslip.com → สร้าง API key (ดูราคา/โควตาฟรีบนเว็บผู้ให้บริการ)
3. **Edge Function** — Supabase → Edge Functions → *Deploy a new function* → *Via Editor*
   - ชื่อฟังก์ชัน: `auto-register` (ต้องตรงตัวนี้)
   - วางโค้ดจากไฟล์ `supabase/functions/auto-register/index.ts` → Deploy
   - (หรือใช้ Supabase CLI: `supabase functions deploy auto-register`)
4. **Secret** — Supabase → Edge Functions → Secrets → Add: `EASYSLIP_API_KEY` = API key จากข้อ 2
   (ถ้ายังไม่ตั้ง: ทุกคำสั่งซื้อจะรอผู้ดูแลตรวจ ไม่ออกรหัสอัตโนมัติ)
5. **ราคา** — เปิด `admin.html` → หัวข้อ *คำสั่งซื้อ* → *ตั้งค่าราคา / บัญชี* → ใส่ราคาต่อชั้น (และราคาเหมา 6 ชั้นถ้ามี)
   บัญชีรับเงินตั้งไว้แล้ว: ธนาคารกรุงไทย 960-0-44146-4 นายเบญจรงค์ นุ่มวัฒนะ

## ทดสอบก่อนเปิดขาย
1. ตั้งราคาชั่วคราวเป็น 1 บาท/ชั้น
2. เปิด `register.html` เลือก 1 ชั้น → โอน 1 บาทเข้าบัญชีร้าน → กรอกข้อมูล + แนบสลิป → ต้องได้รหัสสิทธิ์ทันที
3. ลองส่งสลิปเดิมซ้ำ → ต้องขึ้น "รอเจ้าหน้าที่ตรวจสอบ" (สลิปเคยใช้แล้ว)
4. ใน `admin.html` ลบ/ระงับโรงเรียนทดสอบ แล้วตั้งราคาจริงกลับ

## การดูแลประจำวัน
- `admin.html` → *คำสั่งซื้อ* ตัวกรอง **รอตรวจ** = คำสั่งซื้อที่ตรวจอัตโนมัติไม่ผ่าน (มีเหตุผลกำกับ) → กด *ดูสลิป* ตรวจยอดในบัญชีธนาคาร → *อนุมัติ+ออกรหัส* แล้วส่งรหัสให้ลูกค้าทางแชทเพจ (ลูกค้าแจ้งเลขที่คำสั่งซื้อมา) หรือ *ปฏิเสธ*
- ปิดการออกรหัสอัตโนมัติชั่วคราวได้ใน *ตั้งค่าราคา / บัญชี* (ทุกคำสั่งซื้อจะรอผู้ดูแลอนุมัติ)

## จำลองเหตุการณ์ (ทดสอบโดยไม่ต้องรอให้เกิดจริง)
ตั้ง Secret `EASYSLIP_SIMULATE` ใน Supabase → Edge Functions → Secrets แล้วส่งคำสั่งซื้อทดสอบจากหน้า `register.html`
(ไม่ต้องโอนเงินจริง แนบรูปอะไรก็ได้ — ระบบจะไม่เรียก EasySlip และไม่เสียโควตา)

| ค่า | จำลอง | ผลที่ควรเห็น |
|---|---|---|
| `quota` | โควตา EasySlip หมด | ลูกค้า: "รอเจ้าหน้าที่ตรวจ" · admin: แถบเตือนสีแดง "โควตาตรวจสลิป EasySlip หมด" |
| `unauthorized` | API key ผิด / หมดอายุ | เหมือนข้างบน แต่เตือนให้ตรวจ `EASYSLIP_API_KEY` |
| `down` | บริการ EasySlip ล่ม | เหมือนข้างบน |
| `invalid` | สลิปอ่าน QR ไม่ได้ | ลูกค้าเห็นเหตุผลว่าอ่านสลิปไม่ได้ · admin: รอตรวจ (ไม่มีแถบเตือนระบบ) |

ทดสอบเสร็จแล้ว **ลบ Secret `EASYSLIP_SIMULATE` ออก** (ถ้ายังตั้งไว้ ทุกคำสั่งซื้อจะไม่ได้รหัสอัตโนมัติ)
คำสั่งซื้อทดสอบที่ค้างอยู่ กด *ปฏิเสธ* ในหน้า admin ได้

เมื่อโควตาหมดจริง: ลูกค้ายังส่งคำสั่งซื้อได้ตามปกติ (ไม่ได้รหัสทันที) → admin ขึ้นแถบเตือน → เติมโควตาที่ easyslip.com
→ ตรวจคำสั่งซื้อที่ค้างด้วย *ดูสลิป* + เช็คยอดในบัญชี → *อนุมัติ+ออกรหัส* แล้วส่งรหัสให้ลูกค้า

## เปลี่ยนไปใช้ EasySlip API v2
API v2 (`https://api.easyslip.com/v2/verify/bank`) ตรวจจาก **ข้อความใน QR ของสลิป** (ไม่ส่งรูป)
หน้า `register.html` ถอด QR จากรูปสลิปในเบราว์เซอร์ให้อัตโนมัติ (ใช้ jsQR — `js/vendor/jsQR.js`) และแจ้งลูกค้าทันทีถ้าอ่าน QR ไม่ได้

1. Deploy โค้ด Edge Function ใหม่ (วาง `supabase/functions/auto-register/index.ts` ทับของเดิม)
2. Supabase → Edge Functions → Secrets:
   - `EASYSLIP_VERSION` = `v2`
   - `EASYSLIP_API_KEY` = API key ที่ใช้กับ v2 ได้ (ถ้าบัญชี EasySlip ออก key แยกสำหรับ v2 ให้ใส่ key ใหม่)
3. รัน `sql/orders.sql` อีกครั้ง (เพิ่มการแสดงข้อมูลผลตรวจในหน้าต่าง "ดูสลิป" ของ admin)
4. (แนะนำ) **ลงทะเบียนบัญชีรับเงินในหน้า EasySlip** (เมนูบัญชีธนาคาร / Bank Accounts → เพิ่ม กรุงไทย 960-0-44146-4 แล้วผูกกับ Branch ที่ใช้ API key)
   ระบบส่ง `matchAccount: true` ให้ EasySlip จับคู่ผู้รับกับบัญชีนี้ → ได้เลขบัญชีเต็มกลับมา ตรวจผู้รับได้แม่นที่สุด
   (ถ้าไม่ลงทะเบียน ระบบยังทำงานได้ โดยตรวจชื่อผู้รับ + ธนาคารแทน)
5. ทดสอบโอน 1 บาท (ดูหัวข้อ "ทดสอบก่อนเปิดขาย")

หมายเหตุ v2:
- ผลตรวจ v2 บางรูปแบบไม่มีเลขบัญชีผู้รับ (มีแค่ชื่อผู้รับ + ธนาคาร) — ระบบจะตรวจ **ชื่อผู้รับ (เบญจรงค์) + ธนาคาร (KTB)** แทนเลขบัญชี (ชื่อ/ธนาคารตั้งใน admin → ตั้งค่าราคา / บัญชี)
- ระบบส่ง `matchAmount` (ยอดที่ต้องโอน) ไปด้วย และตรวจยอดซ้ำเองอีกชั้น
- รหัส error ของ v2 ที่ระบบแยกให้: `QUOTA_EXCEEDED` = โควตาหมด · `MISSING_API_KEY`/`INVALID_API_KEY` = key ผิด ·
  `BRANCH_INACTIVE`/`SERVICE_BANNED`/`USER_BANNED`/`IP_NOT_ALLOWED` = บัญชี EasySlip ใช้งานไม่ได้ · `API_SERVER_ERROR` = บริการล่ม
  (ทั้งหมดนี้ลูกค้าเห็นแค่ "ระบบตรวจสลิปอัตโนมัติไม่พร้อมใช้งานชั่วคราว" และ admin ขึ้นแถบเตือน) ·
  `SLIP_NOT_FOUND`/`VALIDATION_ERROR` = สลิปไม่ถูกต้อง (แจ้งลูกค้า)
- **อย่าเปิด IP Whitelist** ในบัญชี EasySlip — Edge Function ของ Supabase ไม่มี IP คงที่ ถ้าเปิดไว้ทุกคำขอจะถูกปฏิเสธ

ถ้า v2 ใช้ไม่ได้ ลบ Secret `EASYSLIP_VERSION` (หรือตั้งเป็น `v1`) จะกลับไปใช้ v1 ทันที
ถ้าคำสั่งซื้อไปรอตรวจทั้งที่สลิปถูกต้อง: admin → ดูสลิป → เปิด "ข้อมูลผลตรวจจาก EasySlip" แล้วส่งข้อความนั้นให้ผู้พัฒนาปรับการอ่านข้อมูล
